## 2. Reverse engineering desde negocio

Usar datos reales de `OFFER.md` y `ANALYTICS.md`.

```text
1. Ingresos objetivo
2. ÷ ticket medio real = ventas necesarias
3. ÷ tasa de cierre real = oportunidades necesarias
4. ÷ tasa lead→oportunidad real = leads necesarios
5. usar relaciones históricas input→output para estimar alcance/interacción/clics necesarios
6. traducir a mezcla de formatos, pilares y frecuencia
```

### Si faltan tasas
No inventar. Crear escenarios explícitos:
- conservador;
- base;
- agresivo;

y etiquetar todos como `HIPÓTESIS` hasta contar con datos.

## 3. Distribución estratégica de contenido

Cuando existan formatos validados:
- 70% formatos validados.
- 20% experimentos nuevos.
- 10% optimización de formatos validados.

### Distribución por función
No usar porcentajes fijos si no hay evidencia. Clasificar cada pieza por función:
- alcance calificado;
- posicionamiento;
- educación/promesa;
- prueba;
- objeción;
- conversión;
- comunidad;
- aprendizaje/formato.

## 7. Reglas de calendario

1. Nunca programar una pieza solo porque “toca publicar”.
2. Nunca aumentar volumen antes de entender qué formatos y mensajes funcionan.
3. Una campaña debe tener relación explícita con la promesa y la jornada del héroe.
4. Viralidad sin relación con marca o negocio no justifica repetición.
5. El calendario debe dejar espacio para zeitgeist cuando el tema sea coherente con valores y posicionamiento.
